# Campus Livre website

Static site for Campus Livre and MatLivre, in English and Brazilian Portuguese. Plain HTML, CSS and a
few lines of JS. There is no build step, no external fonts, no CDN and no tracking.

```
index.html            Campus Livre home
matlivre/index.html   MatLivre product page
assets/               style.css, site.js, favicon, screenshots
.nojekyll             tells GitHub Pages to serve files as they are
```

## Publish on GitHub Pages

1. Create a repository (`campuslivre/campuslivre.github.io` serves at the root of
   `https://campuslivre.github.io/`; any other name serves under `/<repo-name>/`).
2. Push these files to `main`.
3. Settings, Pages, Source: "Deploy from a branch", branch `main`, folder `/ (root)`.

All links are relative, so it works at either kind of URL. For a custom domain, add a `CNAME` file.

## Preview locally

```bash
python -m http.server 8000
```

## Editing text

Every translatable element comes as an `lang="en"` / `lang="pt-BR"` pair; `assets/site.js` shows the
one that matches the visitor's choice (browser language by default). Edit both when you change copy.
Benchmark numbers and limits on the MatLivre page come from the MatLivre README; update them when the
README changes.

## Metadata and link previews

Each page has a canonical URL, Open Graph and Twitter card tags, and JSON-LD (`Organization` and
`WebSite` on the home page, `SoftwareApplication` on MatLivre). Social previews are
`assets/img/og-campuslivre.png` and `assets/img/og-matlivre.png` (1200x630). `robots.txt` and
`sitemap.xml` are at the root, and `404.html` is the not-found page.

The absolute URLs assume the site is published at `https://campuslivre.github.io/`. If it lives
somewhere else (a custom domain, or a project path), replace that base URL in the `seo` block of each
page's `<head>`, in `robots.txt` and in `sitemap.xml`. Social networks need absolute image URLs, and
they cache previews, so test with each network's debugger after the first deploy.

## Languages

English lives at the normal URLs and Brazilian Portuguese at the same path under `/pt/` (`/pt/matlivre/wiki/fn/abs/`), so
search engines and LLM crawlers see one language per URL, with `hreflang` alternates and a sitemap that lists both. The
EN/PT toggle is a pair of real links; `assets/lang-redirect.js` sends a visitor to the language they chose, or, with no
choice yet, from an English page to Portuguese when the browser language, region or timezone says Brazil (never the
other way on its own).

Pages are written once, bilingual (paired elements `lang="en"` / `lang="pt-BR"`), and split by `tools/langsplit.py`:

- `tools/src/index.html` and `tools/src/matlivre.html` are the sources of the home page and the MatLivre page. **Edit
  these, not `index.html` / `matlivre/index.html` / `pt/...`, which are generated.** Put each language's description and
  title in `content="EN" data-pt="PT"` attributes (`<title data-en data-pt>`).
- `python tools/build_wiki.py ...` (below) regenerates every page in both languages, `assets/wiki-search.json` and
  `sitemap.xml`. `404.html` is the one page that still holds both languages (GitHub Pages serves a single 404).

## Wiki

`matlivre/wiki/` is one wiki: a guide (hand-written, `tools/wiki_guide.py`) and one page per MatLivre function
(`matlivre/wiki/fn/<name>/`), plus category pages, a searchable function index and `assets/wiki-search.json` for the
search box. Everything under `matlivre/wiki/` is generated by `tools/build_wiki.py` from:

- `tools/wiki-data/*.json`: the text of each function page (EN and PT-BR), written per function (summary, syntax,
  inputs, outputs, description, notes, examples, see also).
- MatLivre's `docs/matlab-coverage.md` at the release tag (which functions exist) and on master (names marked "next release").
- Real output of every example, produced by `matlivre-cli` and cached in `tools/wiki-cache/outputs.json`.

After a MatLivre release, regenerate:

```bash
git -C ../matlivre show vX.Y.Z:docs/matlab-coverage.md > release-cov.md
python tools/build_wiki.py release-cov.md ../matlivre/docs/matlab-coverage.md --cli ../matlivre/target/release/matlivre-cli.exe
```

New functions without an entry get a placeholder page (`noindex`) and are listed when you build; add them to
`tools/wiki-data/` (check with `python tools/wiki_validate.py FILE.json --cli ...`). Update `VERSION` in the script and the
function count in `matlivre/index.html` too. Syntax highlighting is `assets/highlight.js` (no dependencies).
