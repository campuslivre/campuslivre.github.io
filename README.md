# Campus Livre website

Static site for Campus Livre and MatLivre, in English and Brazilian Portuguese. Plain HTML, CSS and a
few lines of JS. There is no build step, no external fonts, no CDN and no tracking.

```
index.html            Campus Livre home
matlivre/index.html   MatLivre product page
assets/               style.css, site.js, favicon, screenshots
.nojekyll             tells GitHub Pages to serve files as they are
```

## Publish on GitHub Pages

1. Create a repository (`campuslivre/campuslivre.github.io` serves at the root of
   `https://campuslivre.github.io/`; any other name serves under `/<repo-name>/`).
2. Push these files to `main`.
3. Settings, Pages, Source: "Deploy from a branch", branch `main`, folder `/ (root)`.

All links are relative, so it works at either kind of URL. For a custom domain, add a `CNAME` file.

## Preview locally

```bash
python -m http.server 8000
```

## Editing text

Every translatable element comes as an `lang="en"` / `lang="pt-BR"` pair; `assets/site.js` shows the
one that matches the visitor's choice (browser language by default). Edit both when you change copy.
Benchmark numbers and limits on the MatLivre page come from the MatLivre README; update them when the
README changes.

## Metadata and link previews

Each page has a canonical URL, Open Graph and Twitter card tags, and JSON-LD (`Organization` and
`WebSite` on the home page, `SoftwareApplication` on MatLivre). Social previews are
`assets/img/og-campuslivre.png` and `assets/img/og-matlivre.png` (1200x630). `robots.txt` and
`sitemap.xml` are at the root, and `404.html` is the not-found page.

The absolute URLs assume the site is published at `https://campuslivre.github.io/`. If it lives
somewhere else (a custom domain, or a project path), replace that base URL in the `seo` block of each
page's `<head>`, in `robots.txt` and in `sitemap.xml`. Social networks need absolute image URLs, and
they cache previews, so test with each network's debugger after the first deploy.

## Wiki (docs and function reference)

`matlivre/docs/` (how to use the program) and `matlivre/functions/` (every function covered, with search) are
generated by `tools/build_wiki.py`. The docs text lives in that script; the function list comes from MatLivre's
`docs/matlab-coverage.md`. After a MatLivre release, regenerate them:

```bash
git -C ../matlivre show vX.Y.Z:docs/matlab-coverage.md > release-cov.md
python tools/build_wiki.py release-cov.md ../matlivre/docs/matlab-coverage.md
```

Names that are on master but not in the release are marked "next release". Also update `VERSION` in the script and the
function count in `matlivre/index.html`.
