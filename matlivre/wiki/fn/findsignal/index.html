findsignal

Finds the segment of a longer signal that best matches a shorter reference signal.

Category: Feature extraction

Syntax

[istart, istop, dist] = findsignal(data, sig)

Location and distance of the best match.

[...] = findsignal(data, sig, 'MaxNumSegments', n)

Returns up to n best, non-overlapping matches.

[...] = findsignal(data, sig, 'Normalization', 'power')

Normalizes both signals before comparing them.

Description

The reference is slid along data one sample at a time and the distance to each position is computed. The positions with the smallest distance are returned.

With a normalization such as 'power' or 'zscore' the search depends mostly on shape and not on amplitude. Use it to locate a known pulse, beat or pattern inside a long recording.

Input arguments

data
Long signal in which to search, a vector or a matrix with channels in rows.
sig
Short signal to look for.
'MaxNumSegments'
Number of matches to return. Default 1.
'MaxDistance'
Return every match whose distance is below this value.
'Normalization'
'center', 'zscore', 'power' or 'none'.
'Metric'
'euclidean' (default), 'absolute', 'squared' or 'symmkl'.

Output arguments

istart
Index in data where each matching segment starts.
istop
Index in data where each matching segment ends.
dist
Distance between the segment and sig. Smaller is a better match.

Example

Locate a pattern twice in a record

d = [zeros(1,5) 1 2 3 2 1 zeros(1,5) 1.1 2.1 3 2 1 zeros(1,4)];
[s, e, dist] = findsignal(d, [1 2 3 2 1], 'MaxNumSegments', 2, 'Normalization', 'none');
disp(s)
disp(e)
disp(round(dist * 1000) / 1000)
Output
     6    16
    10    20
         0    0.0200

Notes

Only the default time alignment ('TimeAlignment' set to 'fixed') is implemented, so a 'dtw' or 'edr' search gives an error. Windowed normalization with 'NormalizationLength' is not implemented either and gives an error.

See also
